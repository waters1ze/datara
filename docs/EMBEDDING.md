# Embedding Datara in C, C++, and Game Engines

Datara & Forgen provide a first-class C ABI embedding layer designed for game engines, simulation runtimes, and host applications requiring high-performance deterministic execution with minimal binary footprint.

---

## 1. Overview & Profiles

Forgen provides two complementary embedding workflows:

1. **AOT Shared Library (`forgen build --embed [--tiny]`)**:
   Compiles Datara code directly into a native shared library (`.dll` on Windows, `.dylib` on macOS, `.so` on Linux) along with a typed C99/C++ header (`<module>.h`) and the embed runtime header (`datara_embed.h`).
2. **In-Process JIT Embedding (`libforgen` C API)**:
   Embeds the JIT compiler inside your application to dynamically compile, load, and hot-reload Datara modules at runtime.

### The `--tiny` Profile
For game scripting, microservices, and serverless environments, compile with `--tiny`:
```bash
forgen build --embed --tiny
```
- Code generation uses LLVM `-Oz` aggressive size optimization.
- Unwind tables stripped (`-fno-asynchronous-unwind-tables`, `-fno-unwind-tables`).
- Linker dead-stripping (`/OPT:REF`, `/OPT:ICF` on MSVC/lld; `--gc-sections`, `-s` on GNU/LLVM).
- Hello-world shared library footprint $\le 50$ KB with cold start $< 0.5$ ms.

## 2. Embed C API Reference

The embedding API is declared in `datara_embed.h`:

```c
#include "datara_embed.h"

// 1. Initialize the embedding runtime
int32_t forgen_init(void);

// 2. Load and compile a module into process memory
int32_t forgen_load_module(const char* module_path);

// 3. Call an exported function
int32_t forgen_call_fn(
    const char* func_name,
    const int64_t* args,
    size_t arg_count,
    int64_t* out_result
);

// 4. Inspect thread-local errors
const char* forgen_last_error(void);

// 5. Shutdown and release memory
int32_t forgen_shutdown(void);
```

### Argument & Return Value Passing
- Arguments are passed as an array of `int64_t`.
- Primitive numbers (`Int`, `i64`, `i32`) pass verbatim as 64-bit words.
- Floating-point numbers (`Float`, `f64`) pass via standard IEEE-754 bitcast (`double` to `uint64_t`).
- Strings (`Str`) pass as null-terminated UTF-8 C string pointers (`const char*`).
- Pointers to structs/records pass as raw pointers (`intptr_t`).

## 3. Host Embedding Examples

### Minimal C Host Example

```c
#include <stdio.h>
#include <stdint.h>
#include "datara_embed.h"

int main(int argc, char** argv) {
    if (forgen_init() != 0) {
        fprintf(stderr, "Initialization failed: %s\n", forgen_last_error());
        return 1;
    }

    if (forgen_load_module("scripts/gameplay.dtr") != 0) {
        fprintf(stderr, "Failed to load module: %s\n", forgen_last_error());
        forgen_shutdown();
        return 1;
    }

    // Call: fn calculate_damage(base: Int, multiplier: Int) -> Int
    int64_t args[2] = { 100, 3 };
    int64_t result = 0;
    if (forgen_call_fn("calculate_damage", args, 2, &result) == 0) {
        printf("Calculated damage: %lld\n", (long long)result);
    } else {
        fprintf(stderr, "Call error: %s\n", forgen_last_error());
    }

    forgen_shutdown();
    return 0;
}
```

## 4. Game Engine Integrations

### Unreal Engine (C++)
In Unreal Engine, Datara functions can be linked statically or loaded dynamically into `UGameInstance` or gameplay systems:

```cpp
#include "CoreMinimal.h"
#include "Modules/ModuleManager.h"
#include "datara_embed.h"

class FDataraScriptModule : public IModuleInterface {
public:
    virtual void StartupModule() override {
        forgen_init();
        FString ScriptPath = FPaths::ProjectContentDir() / TEXT("Scripts/simulation.dtr");
        forgen_load_module(TCHAR_TO_UTF8(*ScriptPath));
    }

    virtual void ShutdownModule() override {
        forgen_shutdown();
    }
};
```

### Godot 4 (GDExtension)
Use Datara to power deterministic physics calculations or AI behaviors through Godot GDExtension:

```cpp
#include <godot_cpp/core/class_db.hpp>
#include <godot_cpp/classes/node.hpp>
#include "datara_embed.h"

class DataraSimulationNode : public godot::Node {
    GDCLASS(DataraSimulationNode, godot::Node);

public:
    void _ready() override {
        forgen_init();
        forgen_load_module("res://bin/physics.dtr");
    }

    void _process(double delta) override {
        uint64_t delta_bits = 0;
        memcpy(&delta_bits, &delta, sizeof(delta));
        int64_t args[1] = { (int64_t)delta_bits };
        int64_t out_res = 0;
        forgen_call_fn("step_simulation", args, 1, &out_res);
    }

    ~DataraSimulationNode() {
        forgen_shutdown();
    }
};
```

### Raylib
Raylib games can seamlessly link with `--embed` shared libraries for high-performance zero-overhead simulation routines:

```c
#include "raylib.h"
#include "physics.h" // Generated by forgen build --embed

int main(void) {
    InitWindow(800, 600, "Raylib + Datara Simulation");
    SetTargetFPS(60);

    while (!WindowShouldClose()) {
        // Fast deterministic update written in Datara
        update_particles(GetFrameTime());

        BeginDrawing();
        ClearBackground(RAYWHITE);
        draw_particles();
        EndDrawing();
    }

    CloseWindow();
    return 0;
}
```

## 5. Threading & Memory Invariants

1. **Zero-Lock Bump Allocations**:
   Thread-local bump arenas (Tier 1) are partitioned per calling OS thread. Multiple threads can call into Datara functions concurrently without mutex contention.
2. **Determinism**:
   Calculations executed through the embed API are strictly IEEE-754 compliant with lockstep reproducibility across runs.
3. **Graceful Teardown**:
   Calling `forgen_shutdown()` cleanly drains active memory pools and releases all allocated module code.
