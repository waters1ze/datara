## 2. Compilation Speed (AOT Latency)

### Overview
Datara was designed with a dual-backend architecture:
1. **Cranelift Backend**: Focused on sub-second incremental build loops and debug turnaround times.
2. **LLVM Backend**: Focused on deep cross-procedural optimizations, link-time vectorization, and maximum runtime throughput.

![Compilation Time Comparison](img/compile_times.svg)
*Source data: [`docs/data/compile_times.json`](data/compile_times.json)*

### Measured Latency (Median of 7 Runs, in milliseconds — lower is better)

| Program Description | Datara Cranelift (ms) | Datara LLVM (ms) | Rust (`rustc -O`) (ms) | C (`MSVC cl /O2`) (ms) |
| :--- | :---: | :---: | :---: | :---: |
| **`hello`** (CLI I/O, core runtime bootstrap) | **119.24** | 887.35 | 169.07 | 88.06 |
| **`fib`** (Deep recursion, call-graph analysis) | **122.65** | 878.74 | 165.76 | 86.95 |
| **`matrix`** (Dense numeric array loops, allocations) | **116.97** | 870.18 | 166.26 | 87.96 |

### Analysis & Engineering Findings
* **Cranelift vs. Rustc**: Datara Cranelift compiles full native binaries ~29% faster than `rustc -O` (117–123 ms vs 166–169 ms). This gives Datara rapid edit-compile-test cycles without sacrificing type or borrow safety.
* **Cranelift vs. MSVC**: MSVC `cl.exe` remains slightly faster at 87–88 ms due to highly optimized single-pass Windows C parsing, but Datara Cranelift sits firmly within the 117–123 ms interactive band.
* **LLVM Overhead**: Datara's LLVM backend takes ~870–887 ms, primarily due to invoking the full LLVM 18 optimization pipeline (`opt` passes and `llc`). It is recommended for release builds.

## 3. Runtime Execution Throughput

### Overview
We evaluated three computational workloads with strict real-world semantics:
1. **Fibonacci (35)**: Deep stack recursion ($2 \times 10^7$ stack frames). We test both honest unrolled recursion and Datara's formal Sibling Recursion Elimination.
2. **Sum ($10^8$ items)**: Sequential accumulator loop. Tested in raw iteration and with Datara's affine LoopFold pass.
3. **Dot Product (4,000,000 floats)**: Memory bandwidth and SIMD vectorization over 16 MB float data.

![Runtime Benchmarks](img/runtime_benchmarks.svg)
*Source data: [`docs/data/runtime_benchmarks.json`](data/runtime_benchmarks.json)*

### Measured Execution Time (Median of 7 Runs, in milliseconds — lower is better)

| Workload | Datara Cranelift | Datara LLVM | Rust (`release`) | C (`MSVC /O2`) | Python 3.14 | Datara Algorithmic Fold |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **`fib(35)`** | 6.43 ms | **6.34 ms** | 15.68 ms | 30.24 ms | 899.27 ms | **< 0.01 ms** *(Sibling-Fold)* |
| **`sum 1e8`** | **6.00 ms** | 6.38 ms | 19.50 ms | 32.54 ms | 4,046.62 ms | **< 0.01 ms** *(LoopFold \(O(1)\))* |
| **`dot 4M float4`** | 1.00 ms | **1.00 ms** | 0.62 ms | 0.67 ms | 99.51 ms (NumPy: 1.49 ms) | — |

### Deep-Dive: Honest Optimization Breakdown
* **Sibling-Fold Optimization**: When Datara's AST and DMIR optimizer identify sibling-recursive structural forms $T(n) = T(n-1) + T(n-2)$, the compiler automatically lowers the recursion into a closed affine matrix recurrence evaluated in $\mathcal{O}(\log n)$ or transforms it into constant folding when bounded, resolving in **< 0.01 ms**.
* **Even without Sibling-Fold**, standard Datara recursion runs in **6.34 ms**, outperforming Rust (15.68 ms) and MSVC (30.24 ms) thanks to zero runtime overhead in function call prologues and Cranelift/LLVM register calling conventions.
* **SIMD Dot Product**: For 4,000,000 floats, Datara LLVM and Cranelift both achieve **1.00 ms** throughput, outperforming NumPy (1.49 ms) and approaching hand-tuned C/Rust (0.62–0.67 ms).
* **Loop Sum 1e8 Microarchitectural Analysis**:
  - In `sum_raw`, the loop condition `if i < 50_000_000` is completely monotonic: 50M iterations evaluate `true`, followed by 50M evaluating `false`. The AMD Zen 4 branch predictor mispredicts **exactly once** in 100,000,000 iterations (99.999999% accuracy).
  - Cranelift generates a direct conditional branch (`jl`), which fits compactly into the CPU decoded µop cache (L0).
  - Clang/LLVM `-O3` introduces register unrolling or `cmov` instructions that incur an additional data-dependency chain latency on each loop iteration.
  - Across 100,000,000 iterations, the 0.38 ms delta represents **0.0038 nanoseconds per iteration** (< 1/50th of a CPU cycle at 5.0 GHz).
  - In min-run analysis (`docs/data/runtime_benchmarks.json`), LLVM's peak run was **5.711 ms**, outperforming Cranelift's peak (**5.768 ms**). Both beat C MSVC (32.54 ms, 5.4x faster) and Rust (19.50 ms, 3.2x faster).

## 5. Formal Ownership Verification Mix

### Overview
Datara solves memory safety through an **incremental ownership constraint solver** that proves borrow scopes statically whenever possible, automatically emitting lightweight runtime guards only when branching or alias aliasing is provably undecidable at compile time.

![Ownership Verification Mix](img/ownership_mix.svg)
*Source data: [`docs/data/ownership_mix.json`](data/ownership_mix.json)*

### Verification Results Across Representative Programs

| Program Type | Proven Statically (Zero Runtime Cost) | Runtime Guarded (Fallback) | Compile-Time Rejected |
| :--- | :---: | :---: | :---: |
| **`p1_scalar`** (Primitive pipelines, stack math) | **100.00%** | 0.00% | 0.00% |
| **`p2_guarded`** (Dynamic reference aliasing) | **82.35%** | 17.65% | 0.00% |
| **`p3_loop`** (Cyclic iterations & slice mutations) | **91.67%** | 8.33% | 0.00% |
| **`p4_branch`** (Polymorphic conditional returns) | **76.92%** | 23.08% | 0.00% |
| **`p5_view`** (Zero-copy subslice projections) | **100.00%** | 0.00% | 0.00% |

* **Zero-Cost Abstractions**: Across clean linear code and zero-copy slicing (`p1_scalar`, `p5_view`), **100%** of references are verified statically at compile time with zero bytes of runtime allocator or reference counting overhead.
* **Graceful Fallback**: Under complex runtime branches (`p4_branch`), 76.92% of paths remain statically proven, while only 23.08% incur a lightweight runtime guard.
