# DATARA & FORGEN: SYNTAX CLEANUP & SURGICAL DEPRECATION PROMPT
**Назначение:** Четкая инструкция для AI-агента по безопасному удалению устаревшего синтаксиса без случайного повреждения рабочих частей компилятора.

---

### ПРОМПТ ДЛЯ ИСПОЛНИТЕЛЯ (СКОПИРОВАТЬ И ВСТАВИТЬ В ЧАТ):

```text
Ты — Senior Compiler Engineer. Твоя задача — провести хирургическую чистку и унификацию синтаксиса языка Datara в парсере, типизаторе и примерах, строго следуя правилам ниже.

⚠️ КРИТИЧЕСКИЙ ЗАПРЕТ НА ДЕСТРУКТИВНЫЕ ДЕЙСТВИЯ (DO NOT TOUCH):
1. ЗАПРЕЩЕНО трогать или удалять оптимизаторы: Mem2Reg SSA, Dominance CSE, LICM, SROA, LoopFold (сворачивание циклов в формулу Гаусса), Inliner и Evidence Gate.
2. ЗАПРЕЩЕНО ломать кодогенератор Cranelift, рантайм datara_runtime.obj и сборку нативных .exe файлов (~10 КБ).
3. ЗАПРЕЩЕНО удалять работающие тесты — их нужно только аккуратно обновить под новый синтаксис.

ТОЧНЫЙ СПИСОК ТОГО, ЧТО НУЖНО УБРАТЬ И ОБНОВИТЬ:

1. УДАЛИТЬ СТАРЫЙ ОПЕРАТОР `:=`
   - В лексере/парсере объявить оператор `:=` устаревшим (deprecated).
   - При встрече `:=` парсер должен выдавать понятную ошибку:
     "SyntaxError: Operator ':=' is deprecated. Use 'let x = ...' for immutable or 'mut x = ...' for mutable variables."
   - Во всех примерах и тестах заменить `x := ...` на `let x = ...` или `mut x = ...`.

2. УДАЛИТЬ НАСЛЕДОВАНИЕ КЛАССОВ `from`
   - Из грамматики `class` в `src/parser/` удалить ветку `from ParentClass`. Наследование классов полностью упразднено.
   - Заменить его концепцией плоской композиции `using Component` (поля встраиваются напрямую без вложенности).
   - Внимание: НЕ трогать ключевые слова `role`, `behavior`, `component` — они остаются!

3. УДАЛИТЬ АРХАИЧНЫЙ `try / catch`
   - Удалить синтаксические конструкции `try { ... } catch err { ... }` из парсера в пользу `?` и `or { ... }`.
   - В AST и DMIR удалить или пометить как устаревшие узлы TryCatch, не ломая общую структуру инструкций.

4. УНИФИЦИРОВАТЬ ДВОЕТОЧИЕ В ТИПАХ (`name: Type`)
   - Зафиксировать стандарт с двоеточием во всем языке:
     * В параметрах функций: `fn name(param: Type)` (вместо старого `param Type`).
     * В полях классов: `class User { id: u64, name: Str }`.
     * В переменных: `let x: Int = 10` и `mut count: Int = 0`.
   - Парсер должен требовать двоеточие `:` между именем и типом.

5. КАНОНИЧЕСКИЕ ИМЕНА БАЗОВЫХ ТИПОВ
   - Сделать `Str` каноническим коротким именем строкового типа. `String` оставить прозрачным алиасом в типизаторе.
   - Зафиксировать `Int` как алиас для `i64`, `Float` как алиас для `f64`.

ПЛАН ДЕЙСТВИЙ:
1. Внести точечные правки в `src/lexer/mod.rs` и `src/parser/mod.rs`.
2. Обновить резолвер и типизатор (`src/resolver/`, `src/types/`).
3. Обновить синтаксис в файлах примеров (`examples/*.dtr`) и тестах (`tests/*.rs`).
4. Запустить `cargo test` и убедиться, что вся тестовая база (включая SSA-верификатор и оптимизаторы) полностью зеленая (0 ошибок).

Никакого хардкода. Все изменения должны быть чистыми, лаконичными и архитектурно выверенными. Приступай!
```
