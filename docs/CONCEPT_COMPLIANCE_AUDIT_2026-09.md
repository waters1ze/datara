## 1. Честный бенчмарк-срез (kernel-only, checksum verified 4/4)

| Workload | Datara kernel median | Rust kernel median | Соотношение | Compile forgen | Compile rustc | Binary D | Binary R |
|---|---|---|---|---|---|---|---|
| `float_loop` (500M итераций, float) | 301 мс | 321 мс | **0.94x — Datara быстрее** | 88 мс | 202 мс | 10.7 КБ | 163 КБ |
| `int_loop` (500M, `while` + аккумулятор) | 200 мс | **0 мс — rustc свернул цикл в формулу** | не сравнимо (unbounded разрыв) | 88 мс | 194 мс | 9.7 КБ | 163 КБ |
| `box_generic` (200M, generic Box в цикле) | 82 мс | 0 мс — rustc свернул | не сравнимо | 92 мс | 212 мс | 9.7 КБ | 163 КБ |
| `point_sroa` (200M, struct в цикле) | 81 мс | 0 мс — rustc свернул | не сравнимо | 86 мс | 196 мс | 9.7 КБ | 163 КБ |

### Где Datara уже быстрее Rust (измерено)

1. **Compile-время: ~2.2x** (88–92 мс против 194–212 мс на этих workload'ах; ранее 2.5x на других).
2. **Размер бинарника: ~17x** (9.7–10.7 КБ против 163 КБ).
3. **Kernel `float_loop`: 0.94x** — честный победный случай: скалярный float-цикл с тем же результатом до бита, быстрее rustc -O.
4. **Startup:** 6.0–6.6 мс против 5.6–6.8 мс — паритет.

### Где отстаём (безгранично)

- **Приводимые целочисленные ядра** (`int_loop`, `box_generic`, `point_sroa`): rustc распознаёт индукцию и сворачивает цикл в closed form; Forgen исполняет каждую итерацию. Разрыв не в процентах — он «бесконечен» и не закрыт добавлением SIMD.
- Причина: DMIR — не настоящая SSA (loop-carried переменные переиспользуют ValueId), поэтому scalar evolution и dominance-доказуемые трансформации невозможны в полной мере. Существующий loop-closure пасс покрывает только канонический `for`-аккумулятор, а не `while` с индукционной переменной.

### Важный архитектурный нюанс для закрытия разрыва

Wrap-семантика целочисленного переполнения означает, что буквальная замена цикла формулой **не эквивалентна**: итеративный `sum` оборачивается, формула — нет. Честное решение — **спекулятивная closed-form с sound fallback**: быстрый путь считается по формуле только когда trip count доказуемо не переполняет результат (guard по trip count), иначе выполняется исходный цикл. Оба пути дают одинаковый результат при любом входе — семантика сохранена формально, а не «по статистике».

## 2. Zero-cost абстракции: что доказано структурно

`tests/test_zero_cost_proof.rs` (расширен в этой сессии):

- `Point { x, y }` + метод → **0 heap allocations**, CLIF содержит прямые `fmul/fadd`, нет `malloc`, нет vtable-индирекции. Вызов метода объекта инлайнится и скаляризуется — стоимость абстракции равна стоимости ручного кода.
- Дженерики (`Box<Int>`, `Box<Float>`, `Box<Inner>`) — мономорфизация на этапе компиляции, dispatch без рантайм-стоимости.
- Новое (эта сессия): горячий цикл с созданием структуры в теле — проверяется, что SROA устраняет аллокацию и CLIF не содержит heap-вызовов внутри цикла (аналог workload `box_generic` без 200M-итерационного ожидания).

Вывод: zero-cost уровень Rust для OOP/дженериков/структур **подтверждён структурными ассертами на CLIF**, а не только таймингами.

## 4. Выводы

1. **Язык уже живой и быстрый там, где концепция обещала**: compile-скорость, размер, zero-cost OOP/дженерики, нативный скалярный кодекс в пределах 1x LLVM.
2. **Один безграничный разрыв** (приводимые целочисленные циклы) — следствие D1 (не-SSA DMIR); закрывается scalar evolution + sound fallback, не SIMD.
3. **Главная блокирующая работа перед «продом»**: настоящая SSA + механический ворота доверия (Этапы 1–2 плана), затем заморозка спеки (Этап 4).
4. Фичи из видения (машины состояний, bits, contracts, интероп) — после Этапа 4; реализуются как thin поверх готового ядра, в соответствии с принципом «ядро минимальное».
